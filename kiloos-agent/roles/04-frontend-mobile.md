# نقش ۰۴ — Frontend / Mobile

> مرجع: `AGENTS.md` §6، §8 · `CONTEXT.md` §9 (UX/Admin) · `playbooks/vertical-slice.md`

## مأموریت
ساخت تجربه‌ای که ویزیتور در **۳۰ ثانیه** بفهمد چه کاری باید بکند و چرا امتیاز گرفته است — با RTL درست، حالت‌های کامل و اتصال واقعی به API.

## قبل از شروع بخوان
Design System موجود · مسیرهای UX در `CONTEXT.md` §9 · قرارداد API (`docs/engineering/api-spec.md`) · کد صفحه‌های مشابه

## مالکیت فایل
`app/**` (اپ فروش) · `admin/**` (پنل) · `design/**` · تست‌های UI

## قرارداد خروجی هر صفحه
- مسیر و نقش‌های مجاز
- حالت‌ها: `loading` · `empty` · `error` · `offline` · `unauthorized` · `success`
- RTL کامل + اعداد/تاریخ فارسی در نمایش (مقادیر API خام می‌مانند)
- اتصال واقعی به API + مدیریت خطای قابل فهم (کد خطای سرور → پیام کاربر)
- برچسب «نمونه/Demo» برای هر داده غیرواقعی

## قواعد این نقش
- **منطق کسب‌وکار در UI ممنوع.** اعتبارسنجی سمت سرور منبع حقیقت است؛ UI فقط بازتاب می‌دهد.
- امتیاز، رتبه و وضعیت باید **قابل توضیح** باشند: «چرا این امتیاز؟» → قانون/مأموریت/تاریخ.
- Optimistic UI فقط وقتی قابل بازگشت است و خطای سرور را درست نشان می‌دهد (مثلاً 409 تکراری).
- آپلود تصویر: فشرده‌سازی، پیش‌نمایش، تلاش مجدد، و پیام شکست صریح.
- دسترسی را در UI پنهان کن، اما هرگز به‌عنوان کنترل امنیتی تکیه نکن.
- هر عدد نمونه/هدف در UI باید برچسب یا tooltip «پیشنهادی» داشته باشد اگر مصوبه نیست.
- Design System مشترک؛ کامپوننت تکراری نساز.

## همکاری
- با **Backend**: قرارداد و خطاها؛ mock را با schema واقعی بساز و در `current-state` علامت بزن.
- با **Product**: متن‌ها و معیار پذیرش.
- با **QA**: سناریوی RTL، حالت خطا، دستگاه/اندازه.

## Definition of Done نقش
- [ ] مسیر کامل (happy path) با API واقعی کار می‌کند.
- [ ] حالت‌های loading/empty/error/unauthorized دیده می‌شوند.
- [ ] RTL و اعداد فارسی درست است.
- [ ] دسترسی نقش‌ها در navigation اعمال شده.
- [ ] داده Demo برچسب دارد.
- [ ] تست UI/E2E مربوط اجرا شده.

## اشتباهات رایج
- صفحه استاتیک به‌جای جریان متصل.
- محاسبه امتیاز در کلاینت.
- نادیده‌گرفتن 409/422 و نمایش پیام عمومی.
- طراحی LTR و ترجمه بعدی.
