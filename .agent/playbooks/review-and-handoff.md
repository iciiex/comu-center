# پلی‌بوک — بازبینی، ادغام و تحویل بین ایجنت‌ها

> هدف: هیچ تغییری بدون شاهد، سند و قابل‌ادامه‌بودن ادغام نشود.

---

## ۱. چک‌لیست بازبینی PR (ترتیب اهمیت)

### صحت دامنه
- [ ] امتیاز فقط از مسیر Score Event تولید می‌شود؛ منبع و نسخه قانون دارد.
- [ ] idempotency و unique constraint در مسیر امتیاز وجود دارد.
- [ ] تراکنش event + projection + ledger کامل است.
- [ ] اصلاح/برگشت با رویداد جدید است، نه ویرایش.

### دسترسی و امنیت
- [ ] permission و organization scope سمت سرور اعمال شده.
- [ ] تست منفی (403) وجود دارد.
- [ ] ورودی‌ها اعتبارسنجی می‌شوند؛ فایل‌ها محدودیت نوع/حجم دارند.
- [ ] secret/PII جدید در repo یا log نیست.

### داده
- [ ] migration reversible/مستند است؛ داده موجود نمی‌شکند.
- [ ] `NUMERIC` برای امتیاز/مبلغ؛ UUID برای کلید اصلی.
- [ ] index برای queryهای جدید.

### UI
- [ ] حالت‌های loading/empty/error/unauthorized.
- [ ] RTL، اعداد فارسی، پیام خطای قابل فهم.
- [ ] داده Demo برچسب دارد.

### کیفیت
- [ ] تست‌ها اجرا شده و خروجی در PR هست.
- [ ] lint/type-check/build سبز.
- [ ] سند متأثر به‌روز است (یا دلیل «متأثر نیست» نوشته شده).
- [ ] `current-state.md` به‌روز است.

---

## ۲. قواعد ادغام

1. PR کوچک؛ یک هدف؛ یک برش.
2. توضیح PR با قالب `templates/pr.md`.
3. تغییر قرارداد API/DB بدون اعلام به ایجنت‌های دیگر ادغام نمی‌شود.
4. اگر تست اجرا نشده، PR باید صریح بگوید چرا و چه جایگزینی دارد — اما «همه پاس» ننویسد.
5. تغییر قانون امتیاز بدون ADR/decision-log ادغام نمی‌شود.
6. مهاجرت مخرب بدون backup و برنامه بازگشت ادغام نمی‌شود.
7. تعارض با کد قبلی: بازنویسی بی‌صدا ممنوع؛ ثبت و حل.

---

## ۳. Handoff (پایان هر تسک)

`docs/handoffs/current-state.md` را به‌روز کن و این بلوک را بده:

```
MODE: P | H | S
TASK: …
STATUS: Done | Partial | Blocked
CHANGED: مسیر فایل‌ها
CONTRACT: API/DB/قانون (یا «هیچ»)
VERIFIED: فرمان + نتیجه واقعی
DECISIONS: APPROVED / ASSUMPTION / OPEN جدید
RISKS: ریسک باز + trigger
NEXT: فایل/تسک دقیق برای شروع بعدی
```

### قاعده ۳۰ ثانیه
ایجنت بعدی باید در ۳۰ ثانیه بفهمد: کجاست، چه چیزی کار می‌کند، چه چیزی mock است، چه تصمیمی باز است، از کجا شروع کند.

---

## ۴. همکاری چندایجنتی

| وضعیت | کار |
|---|---|
| دو ایجنت، یک فایل | مالکیت را صریح کن؛ یکی بنویسد، دیگری بازبینی |
| قرارداد در حال تغییر | قبل از تغییر، در handoff اعلام کن |
| تعارض تصمیم | به Integrator ببر؛ تصمیم در decision-log ثبت شود |
| کار نیمه‌کاره | در `current-state` زیر «In progress» با شرط تکمیل |

---

## ۵. به‌روزرسانی `current-state` — حداقل‌ها

- تاریخ و به‌روزرسان
- حالت (P/H/S) و milestone فعلی
- Working features (واقعی، تست‌شده)
- Mocked/In progress (با شرط خروج)
- Known issues
- تصمیم‌های تأییدشده و باز
- تغییرات migration/API
- تست‌های اجراشده
- ۳ تسک بعدی پیشنهادی
- فایل‌ها/entry pointهای مهم

اگر این‌ها با واقعیت repo نمی‌خواند، handoff را اصلاح کن — نه اینکه چت را منبع کنی.
