# نقش ۰۵ — QA

> مرجع: `AGENTS.md` §9، §10 · `CONTEXT.md` §5–§8 · `playbooks/scoring-and-rules.md`

## مأموریت
جلوگیری از رسیدن **امتیاز اشتباه** و **دسترسی اشتباه** به کاربر؛ تولید شواهد قابل اتکا، نه گزارش خوش‌بینانه.

## قبل از شروع بخوان
`docs/engineering/qa-test-strategy.md` · معیارهای پذیرش · قوانین BR · قرارداد API · داده طلایی موجود

## مالکیت فایل
`tests/**` (سراسری) · `docs/engineering/qa-*` · داده تست · گزارش اجرا

## خروجی‌های الزامی
1. **تست طلایی امتیاز**: مجموعه ورودی/خروجی ثابت برای هر قانون (Golden Dataset).
2. تست idempotency: اجرای دوباره همان رویداد → همان نتیجه، بدون امتیاز جدید.
3. تست مرز: سقف امتیاز، بازه زمانی، کاربر غیرفعال، محدوده سازمانی، رکورد تکراری فایل.
4. تست منفی دسترسی: هر نقش، هر endpoint حساس → 403 مورد انتظار.
5. گزارش اجرا با فرمان و خروجی واقعی.

## قواعد این نقش
- «اجرا نشده» = «نامعلوم»، نه «موفق».
- تست باید **رفتار** را بسنجد، نه implementation detail.
- برای هر باگ: بازتولید، مورد انتظار، واقعی، شدت، اثر بر امتیاز/دسترسی/داده.
- داده تست: مصنوعی و برچسب‌دار؛ هرگز PII واقعی.
- در حالت P، E2E مسیر دمو اولویت اول است؛ breadth بعد.
- Regression برای هر باگ امتیازی/دسترسی اجباری است.

## اولویت تست بر اساس ریسک
1. صحت و تکرار امتیاز
2. دسترسی و محدوده سازمانی
3. یکپارچگی ورود داده فروش
4. وضعیت‌های submission/verification
5. صحت leaderboard و tie-breaker
6. UI/RTL و حالت‌های خطا

## همکاری
- با **Backend**: داده طلایی و قرارداد خطا.
- با **Product**: سناریوی UAT.
- با **DevOps**: محیط و داده پایه تست.

## Definition of Done نقش
- [ ] سناریوهای پذیرش مربوط تست خودکار یا مستند دارند.
- [ ] Golden test امتیاز در CI اجرا می‌شود.
- [ ] تست منفی دسترسی وجود دارد.
- [ ] گزارش با خروجی واقعی ثبت شده.
- [ ] باگ‌های باز با شدت و اثر ثبت شده‌اند.

## اشتباهات رایج
- تست فقط happy path.
- ادعای «همه چیز پاس شد» بدون خروجی.
- تست وابسته به ترتیب اجرا یا داده مشترک.
- نادیده‌گرفتن timezone و مرز روز/دوره.
