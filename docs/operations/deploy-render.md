# Deploy the demo on Render (MODE: P, D-007 PROPOSED)

> Prototype only: SAMPLE data, SQLite on a persistent disk, one worker. Not production-ready.

## What is in the repo
- `Dockerfile` — python 3.12, `uvicorn app.main:create_app --factory --host 0.0.0.0 --port $PORT --proxy-headers`.
- `render.yaml` — web service `kiloos-club-demo`, 1 instance, disk `kiloos-data` at `/var/data`, health check `/health`.
  A persistent disk needs a paid instance (starter+).

## Environment
| Variable | Value |
|---|---|
| `KILOOS_ENV` | `demo` |
| `KILOOS_DB` | `/var/data/kiloos.sqlite` |
| `KILOOS_EVIDENCE_DIR` | `/var/data/evidence` |
| `KILOOS_SECRET` | generated by Render (`generateValue`), never committed |
| `KILOOS_DEMO_STAFF_CODE` | generated by Render; read it in the Render dashboard and share privately |

## Steps
1. Render dashboard → New → Blueprint → connect the repository/branch that contains `render.yaml`.
2. Wait for the deploy; `/health` must return `{"status":"ok","env":"demo"}`.
3. First boot runs migrations and seeds the demo data **only when the users table is empty**; redeploys never reset it.
4. The seeded competition window expires 7 days after seeding (A4): to refresh, delete the disk data deliberately
   (backup first) or re-seed on the demo morning.
5. Frontend: the Vercel project for `sales-quest-arena` rewrites `/api/v1/game/*` to the Render hostname in
   `vercel.json` — update it if Render assigns a different hostname.

## Login on the hosted demo
- Visitors: pick a visitor on `/login` (or the game picker). No code.
- Staff: open «ورود کارکنان», choose operator/admin, enter `KILOOS_DEMO_STAFF_CODE`.

## Smoke test (external HTTPS)
`/health`; visitor login; `/missions`; operator → `/admin/submissions`; admin → `/admin`; download
`/admin/sales/sample`, upload, process, check `/admin/points` and the import detail; game bootstrap via the
Vercel origin, completion with `Idempotency-Key`, reload; org points unchanged by game play.

## Known limits
SQLite single writer; in-memory rate limit/session state (one worker); evidence on a single disk; demo
accounts are not authentication; PostgreSQL/object storage are deferred to the Harden phase.
